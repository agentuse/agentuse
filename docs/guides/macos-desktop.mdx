The AgentUse desktop app wraps the same local dashboard and `agentuse serve`
runtime used by the CLI. It does not maintain a separate agent configuration or
renderer, so CLI runs and browser access continue to work independently.

## How it behaves

Launching AgentUse opens the dashboard. Closing the window hides it without
stopping the backend, so schedules, approvals, and active runs remain available.
Use the AgentUse menu-bar icon to:

- show the AgentUse dashboard
- open Settings
- quit AgentUse

Settings shows whether the local server is running, lets you start or stop a
server owned by the desktop app, configures launch at login, and displays the
current server log. The Settings window uses native SwiftUI controls while the
dashboard remains the existing web interface. A server started outside the app
is identified as external and is never stopped by the desktop controls. Login
launches start in the background so the menu-bar status and approvals are
available without opening the dashboard window.

**Quit AgentUse** or <kbd>Command</kbd>+<kbd>Q</kbd> stops a backend started by
the app. A backend that was already running when the app launched is left alone.
Only one desktop app instance can run at a time.

The desktop window accepts only the loopback dashboard origin. Links to normal
`http` or `https` sites open in the default browser; other external navigation
is blocked. Electron renderer access to Node.js is disabled and context
isolation is enabled.

## Develop locally

From the repository root, install workspace dependencies and build the existing
CLI and web UI before starting Electron:

```bash
pnpm install
bun run build
pnpm desktop:dev
```

The desktop process attaches to a registered `agentuse serve` daemon when one
is running. Otherwise it starts the compiled local CLI on a loopback port. The
canonical browser dashboard remains available from the URL shown in the menu.

## Build a macOS app

```bash
pnpm desktop:package:mac
```

To create an unsigned development build, run
`CSC_IDENTITY_AUTO_DISCOVERY=false pnpm desktop:package:mac`. For distribution, set
the standard electron-builder signing variables (`CSC_LINK` and
`CSC_KEY_PASSWORD`) and the notarization variables (`APPLE_ID`,
`APPLE_APP_SPECIFIC_PASSWORD`, and `APPLE_TEAM_ID`) in the release environment.
The package configuration leaves hardened runtime enabled and provides a
notarization hook without committing credentials.

The Settings helper normally builds for the current Mac. When producing a
universal Electron application, set `AGENTUSE_SETTINGS_UNIVERSAL=1` so its
nested SwiftUI helper also contains both `arm64` and `x86_64` architectures.

The packaged app includes the existing AgentUse runtime and dashboard assets;
it does not require network access to render the local UI. Model providers and
external tools still have their normal connectivity requirements.

## Troubleshooting

If the window does not load, open **Settings** from the menu-bar item and check
the server status and **Logs** tab. You can also use
the CLI independently:

```bash
agentuse serve ps
agentuse serve logs
```

See [Operations Dashboard](/guides/serve-dashboard) for dashboard behavior and
[CLI Commands](/reference/cli-commands) for the full `serve` reference.
