# Coding-agent integrations

Use AgentUse from Claude Code, Codex, Cursor, or any coding agent that supports
MCP. Ask it to turn the workflow in your conversation into an agent that runs on
its own, or to find and fix agents that fail. Both come from the AgentUse MCP
server on your computer, so every app gets the same version-matched workflow.

## Add AgentUse to your coding agent

- **Claude Code and Codex:** in the AgentUse app or dashboard, open Home (or
  **Settings → Connect apps**) and select **Set up** next to each one. AgentUse
  adds its MCP server to that app's own config and changes nothing else.
- **Any other MCP app:** add your local server as a remote (HTTP) MCP server:
  `http://127.0.0.1:12233/mcp`. For Claude Code by hand:

  ```bash
  claude mcp add --transport http agentuse http://127.0.0.1:12233/mcp
  ```

  If your server uses an API key, send it as a bearer token.

## Use it

```text
Use AgentUse to run the workflow we just completed every Monday at 9am
```

If an app doesn't pick that up, Claude Code has a menu: type `/agentuse` and choose
`automate` or `triage`.

The app checks what your project already has, writes the agent, saves it as a
draft, and practice-runs it with every tool faked. It gives you a review link.
Open it and select **Apply** to turn the agent on, with its schedule if it has
one. A chat can never turn an agent on by itself.

## Work on agent files directly

AgentUse adds no skills on its own. If you'd rather have your coding agent edit
`.agentuse` files and do real runs from the command line, add the `agentuse`
skill yourself. This way has no draft or review step, so check what the agent
changes before you schedule it.

```bash
npx skills add agentuse/agentuse
```

It loads the `core`, `creator`, and `tester` guidance from the installed
AgentUse CLI, so it matches the version that runs your agents.
